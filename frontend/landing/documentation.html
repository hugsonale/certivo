What is Certivo?

Certivo is a motion-based human verification API that stops bots through physics-based challenges. Unlike traditional CAPTCHAs, our system uses real-time facial motion analysis to verify genuine human presence.

Key Features

  • 99.7% bot detection rate - Physics-based verification that can't be faked
  • 10-second verification - Faster than typing a CAPTCHA
  • RESTful API - Simple integration, works with any backend
  • No ML bypasses - Randomized challenges prevent precomputation
  • Privacy-first - Videos analyzed in real-time, not stored
💡 Use Cases
Certivo is perfect for high-stakes verification: crypto airdrops, DAO voting, reward programs, account creation, limited releases, and any scenario where fake users cost you money or credibility.

Quick Start

Get up and running in 5 minutes. This guide walks you through your first verification request.

Step 1: Get Your API Key

Sign up for a Certivo account and generate your API key from the dashboard. You'll need this for all API requests.

✓ Test API Key
Use test_sk_1234567890 for development and testing. This key works with our test environment.

Step 2: Request a Challenge

Call the challenge endpoint to generate a unique verification challenge for your user.

CURL 
curl -X POST https://api.certivo.com/v1/challenge \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "device_id": "device_abc123"
  }'
JavaScript 
const response = await fetch('https://api.certivo.com/v1/challenge', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer YOUR_API_KEY',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    device_id: 'device_abc123'
  })
});

const data = await response.json();
console.log(data);

Authentication

Certivo uses API keys to authenticate requests. Include your API key in the Authorization header of every request.

HEADER Authorization: Bearer YOUR_API_KEY

API Key Types

Key Type Prefix Purpose
Test Key test_sk_ For development and testing. No charges.
Live Key live_sk_ For production use. Real verifications.
⚠️ Keep Your Keys Secret
Never expose your API keys in client-side code, public repositories, or anywhere users can access them. Always make API calls from your backend server.

Getting Your API Key

  1. Sign up for a Certivo account
  2. Navigate to Settings → API Keys
  3. Click "Create New Key"
  4. Copy and securely store your key

Create Challenge

Generate a new verification challenge for a user. Returns a unique challenge with randomized movement instruction.

POST /v1/challenge

Request Parameters

Parameter Type Required Description
device_id string Required Unique identifier for the device/browser
user_id string Optional Your internal user ID for tracking
metadata object Optional Custom metadata to attach to this challenge

Response Fields

Field Type Description
challenge_id string Unique identifier for this challenge
token_id string Security token for verification
instruction string Human-readable instruction (e.g., "Turn your head LEFT")
expected_movement string Movement type: left, right, blink, nod, mouth, eyebrows
difficulty string Challenge difficulty: easy, medium, hard
expires_at timestamp When this challenge expires (5 minutes from creation)

Example Request

cURL 
curl -X POST https://api.certivo.com/v1/challenge \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "device_id": "device_abc123",
    "user_id": "user_456",
    "metadata": {
      "campaign": "airdrop_q1_2026",
      "source": "twitter"
    }
  }'

Example Response

JSON 
{
  "challenge_id": "ch_xyz789",
  "token_id": "tok_def456",
  "instruction": "BLINK your eyes twice",
  "expected_movement": "blink",
  "difficulty": "medium",

Verify Video

Submit a video recording for verification. Certivo analyzes the video in real-time and returns a trust score.

POST /v1/verify

Request Parameters

Parameter Type Required Description
challenge_id string Required The challenge ID from /v1/challenge
token_id string Required The token ID from /v1/challenge
device_id string Required Same device_id used in challenge creation
video file Required Video file (webm or mp4, max 10MB)

Response Fields

Field Type Description
challenge_passed boolean Whether the challenge was successfully completed
trust_score integer Confidence score 0-100 (higher = more trustworthy)
trust_level string low, medium, or high
liveness_score float Liveness detection score 0.0-1.0
session_id string Unique session identifier for tracking
verified_at timestamp When verification was completed
error string Error message if verification failed

Success Response

JSON - 200 OK 
{
  "challenge_passed": true,
  "trust_score": 97,
  "trust_level": "high",
  "liveness_score": 0.96,
  "session_id": "sess_ghi789",
  "verified_at": "2026-03-20T20:15:30Z",
  "movement_detected": "left",
  "processing_time_ms": 1847
}

Failure Response

JSON - 200 OK 
{
  "challenge_passed": false,
  "trust_score": 12,
  "trust_level": "low",
  "liveness_score": 0.23,
  "error": "Movement not detected. Expected: left, Detected: none",
  "error_code": "MOVEMENT_NOT_DETECTED",
  "session_id": "sess_fail123"
}
💡 Trust Score Interpretation
90-100: Very high confidence - Definitely human
70-89: High confidence - Likely human
50-69: Medium confidence - Review recommended
0-49: Low confidence - Likely bot or suspicious

Error Handling

Certivo uses conventional HTTP status codes and detailed error messages to indicate success or failure.

HTTP Status Codes

Code Meaning Description
200 OK Request succeeded
400 Bad Request Invalid parameters or malformed request
401 Unauthorized Invalid or missing API key
404 Not Found Challenge or session not found
429 Too Many Requests Rate limit exceeded
500 Internal Server Error Something went wrong on our end

Error Response Format

JSON 
{
  "error": {
    "code": "INVALID_CHALLENGE",
    "message": "Challenge has expired or does not exist",
    "details": {
      "challenge_id": "ch_xyz789",
      "expired_at": "2026-03-20T20:00:00Z"
    }
  }
}

Common Error Codes

Error Code Description Solution
INVALID_API_KEY API key is invalid or missing Check your Authorization header
INVALID_CHALLENGE Challenge expired or not found Generate a new challenge
VIDEO_TOO_LARGE Video exceeds 10MB limit Reduce video quality or duration
NO_FACE_DETECTED No face found in video Ensure good lighting and face visibility
MOVEMENT_NOT_DETECTED Expected movement not performed User should retry with correct movement
VIDEO_INTEGRITY_FAILED Video appears fake or manipulated Video may be pre-recorded or deepfake
RATE_LIMIT_EXCEEDED Too many requests Wait before retrying

Best Practices

Follow these guidelines to get the best results from Certivo.

1. Device Fingerprinting

Generate a stable device_id using browser fingerprinting. This helps Certivo build trust over time.

JavaScript 
// Generate stable device ID
function getDeviceId() {
  let deviceId = localStorage.getItem('certivo_device_id');
  
  if (!deviceId) {
    // Generate new ID from browser fingerprint
    deviceId = btoa(
      navigator.userAgent + 
      screen.width + 
      screen.height + 
      Date.now()
    );
    localStorage.setItem('certivo_device_id', deviceId);
  }
  
  return deviceId;
}

2. Handle Failures Gracefully

Allow users to retry failed verifications. Show clear, helpful error messages.

✓ Good UX
"We couldn't detect your face. Please ensure you're in good lighting and try again."
✗ Bad UX
"ERROR: NO_FACE_DETECTED"

3. Set Appropriate Thresholds

Decide what trust_score to accept based on your risk tolerance:

  • High Stakes (Airdrops, Voting): Require 80+ trust score
  • Medium Stakes (Account Creation): Require 60+ trust score
  • Low Stakes (Newsletter Signup): Require 40+ trust score

4. Implement Rate Limiting

Limit verification attempts per user to prevent abuse:

  • 3 attempts per hour per device
  • 10 attempts per day per IP
  • Block devices with repeated failures

5. Monitor and Alert

Track key metrics and set up alerts:

  • Overall pass/fail rate
  • Average trust score
  • Verification completion time
  • Spike in failed attempts (potential attack)

HTTP Headers

Handling Rate Limits

JavaScript 
const response = await fetch('https://api.certivo.com/v1/challenge', options);

if (response.status === 429) {
  const resetTime = response.headers.get('X-RateLimit-Reset');
  const waitSeconds = resetTime - Math.floor(Date.now() / 1000);
  
  console.log(`Rate limit exceeded. Retry in ${waitSeconds} seconds.`);
}
