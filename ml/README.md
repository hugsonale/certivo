# The Certivo ML workspace (step P0-30)

Where models are trained, measured and written up, so that **any result can be reproduced from a clean checkout** and **data never ends up in git**.

> **What is here today.** A *baseline experiment on synthetic data* (pictures generated by this repository, containing no people). It exists to prove the machinery works.
> It says nothing about real-world accuracy, and no number from it may be quoted. Real data needs an approved data sheet first (step P0-31).

## The pieces

| Piece | What it does | Where |
| :-- | :-- | :-- |
| **DVC** | Runs the experiment as a pipeline and fingerprints every input and output, so "what produced this?" always has an answer. Data and models are kept by DVC, not by git. | `dvc.yaml`, `dvc.lock` |
| **MLflow** | Keeps a record of each run: settings, results, code version, data fingerprint, tool versions. Records stay on your computer. | `certivo_ml/tracking.py`, `mlflow/` (not committed) |
| **Settings** | Every number that shapes an experiment, in one file, so a change shows in git. | `params.yaml` |
| **Model cards** | One page per model, written FROM the metrics file so it cannot disagree with it. It refuses to boast and must state its promotion status. | `model_cards/` |
| **Data sheets** | A page per dataset, filled in before the data is used. | `datasheets/` |
| **The guard** | Fails if a picture, video, sound, array, model weights, table or archive is committed under `ml/`. | `scripts/check_no_data.py` |
| **Pinned tools** | Exact versions of everything, so the same code gives the same result. | `requirements.txt`, `constraints.txt` |

(The guide says to use the v1 documents' tools "once known". Those documents did not reach me, so these are the fallback it names: DVC and MLflow.)

## Set up (once)

All commands are for Git Bash on Windows. You need **Python 3.12 or 3.13, 64-bit** (3.12 is what the pins were made with; CI tests both). Not 3.11 (too old for the pinned NumPy) and not 3.14 or 3.15 (some tools have no ready-made Windows files for them yet).

```
py -0
```

lists the Pythons you have; look for `3.12` or `3.13`. If neither is there, install one from python.org first (leave "Add python.exe to PATH" unticked, so your default does not change). Then, with `3.13` below replaced by `3.12` if that is the one you have:

```
cd ~/desktop/exclusive/certivo/ml
py -3.13 -m venv .venv && source .venv/Scripts/activate && python scripts/check_environment.py && pip install -r requirements.txt -c constraints.txt
```

The `&&` makes it stop at the first problem. `check_environment.py` says in one line if the Python is wrong, instead of letting pip fail with pages of build errors.

It takes a few minutes (MLflow brings many packages). Every later session starts with `cd ~/desktop/exclusive/certivo/ml` and `source .venv/Scripts/activate`.

## Run the baseline

```
dvc repro
```

It makes the data, trains, evaluates and writes the model card, in order, skipping anything already up to date. Then:

```
dvc metrics show
```

shows the results. The model card is `model_cards/baseline-synthetic-v0.md`.

To look at the experiment records in a browser (this computer only):

```
mlflow ui --backend-store-uri sqlite:///mlflow/mlflow.db
```

then open http://127.0.0.1:5000.

## Prove it reproduces from a clean checkout

```
python scripts/clean_checkout_repro.py
```

It clones what is **committed** (so commit your work first) into a temporary folder, builds a brand-new environment there, re-runs every stage, and checks that `dvc.lock`, the metrics and the model card come out **byte for byte the same**. It prints PASS or FAIL. (It needs internet to install the tools, and takes a few minutes.)

## Checks

```
python -m pytest tests -q
python scripts/check_no_data.py
```

CI runs both on every pull request, plus `dvc repro --force` and a check that nothing changed.

## Rules for data (never skip these)

- **Never commit data.** Not pictures, not video, not sound, not arrays, not model weights, not CSV tables. `.gitignore` is the first defence and `check_no_data.py` the last; if the guard complains, do not argue with it: `git rm --cached <file>`.
- **No data is used before its data sheet is finished** (`datasheets/TEMPLATE.md`): where it came from, who agreed, and its licence. Many public datasets forbid commercial use. **No scraping of people's faces.**
- **The test split is touched once**, to report a result. Choices (like the temperature here) are made on the validation split. A test checks that changing the test split cannot change the trained model.
- **A model card is generated, never hand-written**, and says "Not promoted" until the promotion gate (P0-40) is passed. Nothing is said outside the company about a model's accuracy before that.

## Adding an experiment

1. Put its settings in `params.yaml`.
2. Add stages to `dvc.yaml` (data, train, evaluate, card), each listing what it needs and what it makes.
3. Log the run with `certivo_ml/tracking.py` and write the card with `certivo_ml/model_card.py`.
4. `dvc repro`, run `python scripts/clean_checkout_repro.py`, then commit `dvc.lock`, the metrics file and the card (and nothing else generated).
